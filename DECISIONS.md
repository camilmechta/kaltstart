# Decisions

| # | Decision | Reason | Options rejected |
|---|---|---|---|
| D1 | Portfolio first, continuation conditional on thresholds | A threshold fixed before the test shows a product approach | Portfolio only; real product from the start |
| D2 | Thresholds of 10 % human responses and 3 % positive responses | Above a generic mail, with enough volume to conclude | 5 %; 15 % |
| D3 | Requests limited to internship or part-time | A precise request makes the test comparable | Internship only; any type of request |
| D4 | One or two concrete examples written by the student | The only part that tells one student from another, without AI | Structured fields only; one example per role |
| D5 | 3 mails per company over 30 days, counted at generation | Protects the founder; the app always sees the generation | No limit; counter without blocking; counting at declared send |
| D6 | "Copy" buttons, limit of 5 pending mails | Matches real usage; pushes students to keep tracking up to date | `mailto:` button; hidden blind copy address |
| D7 | Named address only if published | Every address has a verifiable source; no bounces | Generic always; guessed address |
| D8 | Scraper thresholds at 70 % and 40 % | Checkpoint before investing in phases 3 to 5 | 50 %; 85 % |
| D9 | FastAPI for generation, GitHub Actions for the nightly job | Python must run on click; the nightly job needs no server | Queue in the database; templates rewritten in JavaScript |
| D10 | Mails presumed sent are excluded from the rates | It is unknown whether they left; they would distort the metric | Counting them as sent |
| D11 | Sign-up with an invitation code, no domain check | Simpler, no dependency on university mailboxes, control over who joins | Mandatory HSG address; open sign-up |
| D12 | Several template styles, style stored with each mail | The student picks the tone; the test compares styles | A single template |
| D13 | Public repository documents in English (README, PRD, DECISIONS, CHANGELOG, CLAUDE.md, code and commits) | Readable by European tech recruiters | French |
| D14 | Package `src/kaltstart/` instead of `src/ingestion/` directly | A single package name avoids import conflicts | One top-level package per component |
| D15 | Nightly synchronisation through `/changes` | It is the mechanism the API provides for synchronisation, and it also reports deletions | Re-reading `/rounds` every night |
| D16 | The sync watermark counts only successful `backfill` and `sync` runs; interrupted runs are recorded as failed | A successful details or reclean run must not hide a failed sync | Latest successful run of any command; interrupted runs left unrecorded |
| D17 | The details fetch stops and fails after 3 consecutive failures | Do not hammer a failing API; make systemic failure visible | Continue through every company; stop at the first failure |
| D18 | A repeated pagination cursor or an incomplete removed list is an error | A visible failure is better than silent data loss | Stop silently and record success |
| D19 | Weekly `backfill` every Sunday, in addition to the nightly `sync` | `/changes` reports added and removed rounds only, so edits to known rounds (such as an amount published later) would never arrive; a re-read costs about ten requests | Accept stale rounds; re-read `/rounds` every night |
| D20 | The design spec and the implementation plans are in English too, extending D13 to every file in the repository | The repository is public; a reader should not hit a language switch between the code and its design documents | Keep the spec and plans in French |
| D21 | A round missing a required field (date, identifier, page link, or the company's identifier, name, country or page link) is skipped and listed in the run summary, not stored | `/changes` can report a freshly created round before Tech.eu completes it (a null date was seen live on 2026-11-12); such a round cannot be placed in the 12-month window or stored under the schema. The weekly backfill picks it up within a week once it is complete, as long as it falls in the 12-month window | Use `createdAt` as the date; fail the run |
| D22 | Size bounds for rounds without a known stage set to 7 and 20 million euros (were 3 and 15) | Calibrated on the first load (2026-11-12, 832 rounds): median amounts are 2.0M for Pre-Seed, 4.3M for Seed, 12.0M for Series A and 31.8M for Series B, so each bound is a round figure between the medians of the two stages it separates. This assumes rounds without a known stage are distributed like the others, which is not verified. With 3M, more than half of Seed-sized rounds would have been classified medium | Keep 3 and 15; fit the bounds on the full distribution |
| D23 | Measure the contact scraper on 20 sites before building the nightly run and the database writes | The measurement is a checkpoint: if it fails, the method changes and anything built around it would be redone | Build the whole phase at once |
| D24 | The scraper reads the raw HTML of pages, without a browser | Fast, free and simple to run; the measurement shows how many sites need JavaScript | A real browser from the start; a browser as a fallback now |
| D25 | The scraper follows the home page's links by keyword, with fixed paths as a fallback | Sites use many names for the same page, in two languages; guessing paths mostly yields missing pages | Fixed paths only |
| D26 | Only addresses on the company's domain are kept; the others are counted as a failure cause | Protects against addresses of third parties; the count shows whether the rule costs too much | Keep any address found on the site |
| D27 | The scraper does not announce the project in its `User-Agent`, and does not imitate a browser | The project owner does not want the repository linked from site logs; pretending to be a browser would work around sites that refuse robots. Replaces "a tool name that identifies the project" in the design spec | A named bot with a link to the repository; a browser `User-Agent` |
| D28 | Detailed measurement results stay on the owner's machine; the repository holds only the sample and a summary without names or addresses | The repository is public; a file of founder names and addresses would be a ready-made contact list | Commit the full results |
| D29 | First verification pass by an assistant, then the owner confirms the finds and checks 5 companies independently | Keeps an independent human check at about half an hour of the owner's time | Owner checks all 20; no independent check |
| D30 | A measurement result within one company of a threshold is inconclusive, and 20 more companies are drawn | One company is 5 percentage points | Decide on 20 whatever the result |
| D31 | Redirects are followed by hand and each hop is checked before it is requested; social networks are never requested | The HTTP client followed redirects on its own, so a page redirecting to LinkedIn or a job board was fetched before the same-site check ran | Let the client follow redirects and drop foreign pages afterwards |
| D32 | A `robots.txt` that cannot be read (network error, 5xx) forbids the site; each host's own file is read; rules for the scraper's `User-Agent` are obeyed | Obeying `robots.txt` is a hard rule, and RFC 9309 asks to assume everything is disallowed when the file is unreachable. Replaces "unreadable means no restriction" | Treat an unreadable file as no restriction; check `*` rules only |
| D33 | Bare words are never read as an address; only the bracketed lower-case forms are | A heading such as "Jobs at Example.ch" became `jobs@example.ch`, an address nobody published | Accept `local at domain` when it is the whole text of an element |
| D34 | The parent of a site's host counts as the company's domain only for generic subdomains (`app.`, `shop.`) | For `startup.ethz.ch` or `startup.webflow.io`, the parent belongs to a university or a site builder | Trust any parent with two labels; add a public-suffix library |
| D35 | A personal address needs the founder's last name, or is exactly the first name; founder extraction binds each role to its nearest name and never takes a label as a name | `anna.schmidt@` was typed as the address of a founder called Anna Muster, and "Vertretungsberechtigte Person" was returned as a founder; a wrong name ends up in a mail | First or last name anywhere in the local part; first role of the block for every name in it |
